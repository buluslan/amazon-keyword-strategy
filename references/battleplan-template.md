# 作战图模板 · 字段规范与渲染规则

> Step 4 落盘时读本文件。定义作战图的字段、分块、标注规则与落盘结构。
> 取数类（落盘路径、文件名、标注符号）钉死执行；判断类（竞争强度档位、建议动作、阶段性归类）给 Agent 判断空间，但必须基于下述锚点。

---

## 1. 落盘约定（钉死）

目录：`output/{ASIN}_{日期 YYYYMMDD}/`，固定三个文件（**文件名自描述**：类型打头 + ASIN + 日期——单文件脱离文件夹后仍有完整上下文，转发/搜索可辨）：

| 文件 | 内容 | 格式 |
|---|---|---|
| `关键词作战图_{ASIN}_{日期}.xlsx` | 精准词表 + 否定词表 + PPC策略（多 sheet） | 表格 |
| `关键词作战图_{ASIN}_{日期}.md` | 可读总结：判别结论 + 词表摘要 + 策略要点 | markdown |
| `关键词词表_{ASIN}_{日期}.json` | 全量结构化词数据（供下游脚本消费） | JSON |

- 日期取当天；同一 ASIN 同日重跑覆盖，跨日累积。
- 命名锚点逐级兜底：**本品 ASIN > 词表名（payload `name`）> 核心关键词 > 首个竞品 ASIN > "词表"**——新品建库场景本品可能未上架/未提供 ASIN，文件名仍需自描述。输入是本品 ASIN 时照旧用本品 ASIN；竞品反查建库时优先问用户要本品 ASIN（有则用），没有落到核心关键词。锚点经文件名清洗（非法字符/空格→连字符）后**目录名、三件套文件名、md 标题三处共用**，实际值回写 json 顶层 `name_anchor`。
- 顶层 `competitor_asins`（本次反查的竞品 ASIN 清单，无则空数组）随 json 落盘，留审计口径。

---

## 2. 基础层 vs 增强层

分析层只需"关键词"即可跑核心逻辑；增强字段缺失时降级，永不停摆。

| 层级 | 前置字段 | 输出能力 |
|---|---|---|
| **基础层** | 仅关键词 | 词根分类 + 匹配建议 + 否定词 + 阶段性标记 |
| **增强层** | 关键词 + 搜索量 + 竞争指标 + 转化 | 上面全部 + 大中小词分层 + 竞争强度 + PPC 策略 + 蓝海词识别 |

- 增强字段缺失 → 跑基础层，相关列标 `[缺失]`，不脑补数字。
- 未实测（估算/推断）字段标 `⏳`，并注明推算依据。

## 3. 标品作战图（4 部分）

### 3.1 精准词表

| 字段 | 说明 | 缺失处理 |
|---|---|---|
| 关键词 | 原始词，去重后保留 | 必填，无则丢弃该行 |
| 搜索量 | 月搜索量（int） | 标 `[缺失]`，分层跳过 |
| ABA排名 | ABA 搜索频率排名原始值（全站统一绝对标尺，跨品类可比） | 源未返回标 `[缺失]` |
| ABA层级 | **固定界限切档（render 计算，可复现）**：≤1万 大词 / 1万~10万 中词 / 10万~50万 小词 / >50万 长尾（界限为行业经验锚点）；无排名时按本表搜索量分位兜底（≥P80 大 / ≥P50 中 / ≥P20 小 / 其余长尾） | 排名与搜索量都缺标 `[缺失]` |
| 竞争分 | 0-100 确定性打分（公式见下），render 计算 | 竞争指标全缺标 `[缺失]` |
| 竞争强度 | **固定切点（render 计算）**：竞争分 ≥70 高 / 40~69 中 / <40 低 | 竞争分缺失标 `[缺失]`，不下结论 |
| 词根类型 | 共性/属性/品牌/品类/受众/否定（六分类）；属性词带维度：`属性·<维度>`（如 `属性·尺寸`，维度现场归纳，见 word-root-classification.md） | 必填 |
| 建议匹配 | 精准/词组/广泛 | 由竞争强度 + 词根类型推导 |
| 建议动作 | 主攻/截流/广泛铺词/观察/否定 | 由词根类型 + 竞争强度推导 |
| 阶段性 | 新品/成长/成熟/衰退（**词维度**：该词适合在哪个阶段主打；强依据=趋势数据，弱依据=词规模推断标⏳，语义见 play-analysis-engine.md §1.5） | 两依据都缺标 `[缺失]` |

**竞争分公式**（确定性，指标槽按本次词表可用字段动态命中）：

```
竞争分 = mean(Top3点击集中度, Top3转化集中度, mean(占位率各档), …其他可用指标) × 100
档位：≥70 高 / 40~69 中 / <40 低（固定切点，同一输入永远同一输出）
```

- 0-1 型指标（点击/转化集中度、占位率）直接用原值；占位率族先组内平均再与其他槽等权；SPR/商品数等非归一指标按本表 min-max 归一。
- 指标缺失跳过（不充零），全缺标 `[缺失]`。
- 本次实际命中的指标清单由 render 自动写入 `data_notes.competition_basis`（口径自动交代，不用 Agent 手填）。
- 源独家指标（如 SIF 占位率）按"跨源共有语义槽"原则作为竞争分输入，不单独成列。

**建议动作映射**（词根类型驱动，Agent 可调）：

- 共性词 / 属性词 → 主攻（精准或词组）
- 竞品品牌词 → 截流（精准，控预算）；**本品品牌词 → 主攻**（归共性/属性处理，详见 word-root-classification.md 品牌词根双分类）
- 品类词 → 视竞争强度（高精准 / 低广泛）
- 受众词 → 观察或长尾广泛
- 否定词 → 移入否定词表

### 3.2 否定词表

| 字段 | 说明 |
|---|---|
| 关键词 | 判定为否定的词 |
| 所属否定词根 | 该词所属的否定词根族（如 adapter 族），同族词归组 |
| 否定原因 | 不相关 / 低转化 / 品牌竞品词误触 / 泛流量 |
| 否定类型 | 精准否定 / 词组否定 |

- 否定原因标注要具体（如"搜索意图偏配件，与本品不符"），不写"不相关"一句话。
- 一词可同时给精准否定 + 词组否定建议，但注明优先级。
- **词根级否定优先**：同族词优先建议词组否定（否一个词根拦整族衍生长尾），判定规则见 `word-root-classification.md` 否定词根节。

### 3.3 PPC 策略建议（增强层）

PPC 四象限（搜索量×竞争强度）的完整判定逻辑见 `play-analysis-engine.md` §1.4。本节只定义输出格式：

- `ppc_quadrant` 由 render 按 **ABA层级 × 竞争强度档** 确定性交叉计算（量高=大词/中词）：量高竞低=蓝海主攻 / 量高竞高=精准控预算 / 量低竞低=长尾广泛 / 量低竞高=不建议打。Agent 不再逐词标注。
- ABA层级或竞争强度任一缺失 → 该词不进四象限，标"数据不足，待补"。
- 策略建议落到具体动作（匹配类型、预算倾向、是否主攻）。

### 3.4 词根汇总（族级聚合视图）

一行一个词根（token 级），把千条长尾压缩成需求结构速览：

| 字段 | 来源 | 说明 |
|---|---|---|
| 词根 | render 现场聚合（token 分词统计） | 运行时从词库生长，零预置 |
| 属性维度 | Agent 归纳（`root_dims` 注入，可选） | 该 token 属什么维度（尺寸/风格/接口…），未注入标 `[缺失]` |
| 命中关键词数 | render 统计 | 该词根衍生多少条词 |
| 搜索量合计 | render 统计（含搜索量的词求和） | 缺失标 `[缺失]` |
| 示例词 | render 取样 | 前 3 个命中词 |

- 用途：10 秒看懂需求结构（哪些维度是主流需求）；埋词覆盖核心词根即可触达整族衍生长尾。
- 维度归纳是判断类动作，归 Agent；聚合统计是取数类，render 自动完成（措辞边界）。

### 3.5 字段说明 sheet（每个字段的就地解释）

xlsx 固定第 5 个 sheet，一行一个字段：**字段 / 含义 / 怎么判定的**。两层来源：

- **机制说明（render 写死）**：字段定义与判定框架——六分类各类含义、属性·<维度> 的现场归纳机制、竞争强度"任一高=高/全低=低/否则中"锚点、ABA 按本表分布分层、四象限定义、品牌双分类。这些跨任务稳定。
- **运行时口径（`data_notes`，render 渲染进对应行）**：每次跑都会变的——搜索量时间单位（周/月）、阶段性的数据基础（有无上架/趋势数据）、⏳ 待确认项清单由 Agent 注入；**竞争强度本次实际依据的指标清单由 render 自动生成**（基于竞争分实际命中的指标槽，保证口径与计算一致，不用 Agent 手填）。

`data_notes` 结构（payload 可选字段，缺失时对应说明标 `[缺失]`）：

```json
{
  "search_volume_unit": "周",
  "competition_basis": "竞争分 = Top3点击集中度(2134词) + Top3转化集中度(2134词) + 占位率(族内均值)(2134词)（等权均值×100）；档位固定切点：≥70 高 / 40~69 中 / <40 低",
  "stage_basis": "无上架时间/趋势数据，按 PPC 四象限推断，标 ⏳",
  "observations": ["反查接口翻页参数失效，单页 50 词上限，已用流量词接口补足"],
  "notes": ["本品关键规格按词库词频推断，⏳[待确认]"]
}
```

`data_notes` 三类语义（渲染处理不同）：`notes` = 待确认项（渲染带 ⏳ 前缀）；`observations` = 诊断要点/数据局限（事实性说明，渲染不带 ⏳——不要把数据源局限打成待确认）；`warning` = 结构失配警示（render 自动计算写入：否定词占比 > 80% 时触发，Agent 不手填）。

**为什么占位率/点击集中度没有单独列**：它们是竞争强度判定的**输入**，不是独立交付字段——源独家指标（如 SIF 占位率）按"跨源共有语义槽"原则并入 competition 判定，不单独成列（换源即缺列）。本次用了哪些输入，由 `competition_basis` 交代。

### 3.6 md 判读说明节（作战图.md 开头规范）

md 总结开头（判别结论之后）固定带「判读说明」节：数据口径（搜索量单位/竞争依据/阶段基础）+ ⚠️ 失配预警（有则渲染）+ 诊断要点（observations）+ ⏳ 待确认清单 + 边缘词处理说明（如 borderline 词为何没否定）。数据从 `data_notes` 渲染；Agent 分析阶段必须产出 `data_notes`（分析层职责，见 play-analysis-engine.md §3.1）。

**两段式 md**：md = render 骨架（判读说明/词表等机械节）+ Agent 策略段（`payload.strategy_summary` 注入，渲染为「策略要点」节：打法要点/广告组架构/场景专项结论）。策略段走 payload 通道而非落盘后手工追加——同日重跑 render 整文件覆盖时，Agent 分析不丢。

### 3.7 原始数据 sheet（数据源留底）

经数据源/MCP 反查获取的词表，把**适配器返回的全字段原始数据**落进 xlsx 第 6 个 sheet 留底——数据过了这村没这店，留底才能审计口径、二次分析、复跑对比。

- **内容**：payload keywords 中判定字段（word_root / match_type / action / stage / ppc_quadrant）之外的**全部字段**（搜索量/竞争原始指标/转化/竞价/排名等），动态表头（字段并集，源不同字段不同），核心字段中文列名，未映射字段透传原名。
- **出现条件**：词表存在任一增强字段（搜索量/竞争/转化等）→ 出该 sheet；纯关键词输入（粘贴）无原始数据，不出。
- **词表.json / 作战图.md 结构不变**（json 本身已含全字段，留底只补 xlsx 侧）。

## 4. 非标品输出

非标品出基础作战图三件套（同 §3 结构）：判别结论写进 md 总结 + 精准词表 + 否定词表。匹配建议整体偏广泛/词组铺长尾（出单词分散，精准单点效率低），否定词判定逻辑同标品。

---

## 5. 渲染规则（钉死）

1. **缺失标注**：字段缺失统一标 `[缺失]`，不用空格、不用"-"、不用"未知"。
2. **未实测标注**：估算/推断值标 `⏳`，并在 md 总结里注明推算依据（如"搜索量按品类均值估算"）。
3. **数据来源标注**：md 总结开头注明本次数据来自哪些可用数据源；混源时标每个字段来源。
4. **不脑补数字**：搜索量、竞争指标、竞价等数值字段，没有就 `[缺失]`，绝不填估算当实测。
5. **词表去重**：同一词只保留一行，多源数据合并到同一行（取最优字段）。
6. **排序**：精准词表默认按搜索量降序（缺失排末尾）；否定词表按否定类型分组。

## 6. `词表.json` 结构（最小）

```json
{
  "asin": "B0XXXXXX",
  "competitor_asins": ["B0YYYYYYY", "B0ZZZZZZZ"],
  "core_keyword": "核心关键词（竞品反查场景用户提供了才有，可缺省）",
  "name": "词表名（词表输入可选，命名兜底链第 2 级）",
  "name_anchor": "本次实际使用的命名锚（render 回写，与目录/文件名/md 标题一致）",
  "strategy_summary": "Agent 产出的策略要点段（string 或 string[]，可选）",
  "date": "YYYYMMDD",
  "verdict": "标品 | 半标品 | 非标品（判别细则见 standard-vs-nonstandard.md，中间态合法输出）",
  "data_sources": ["源A", "源B"],
  "root_dims": { "queen": "尺寸", "boho": "风格" },
  "keywords": [
    {
      "keyword": "...",
      "search_volume": 1200,
      "aba_rank": 8085,
      "aba_tier": "大词",
      "competition_score": 82,
      "competition_level": "高",
      "ppc_quadrant": "精准控预算",
      "word_root": "属性·尺寸",
      "match_type": "精准",
      "action": "主攻",
      "stage": "成长",
      "source_asin": ["B0YYYYYYY", "B0ZZZZZZZ"]
    }
  ],
  "negatives": [
    { "keyword": "...", "root": "adapter", "reason": "...", "negate_type": "词组" }
  ],
  "root_summary": [
    { "token": "queen", "attribute_dim": "尺寸", "keywords_count": 340, "search_volume_sum": 580000, "sample_keywords": ["..."] }
  ]
}
```

- 增强字段缺失的词，对应 key 设 `null`，不省略 key（下游脚本可判空）。
- `competitor_asins` 顶层字段无则空数组（render 兜底写入）；`asin` 位的取值规则见 §1 命名锚点兜底。`name_anchor` / `date` 由 render 回写；`strategy_summary`（策略段通道）与 `data_notes.observations`（诊断要点）见 §3.5/§3.6。
- `source_asin`（词级）：该词来自哪些反查 ASIN 的数组——多竞品合并场景由 `normalize_to_schema(source_asin=...)` + `dedup()` 自动产生，数组长度 = 竞品覆盖数（见 adapter-interface.md §五·五）；词表输入无此字段（render 统一补 `null`）。**不进精准词表列**（留位不臃肿），落在 json 与原始数据 sheet。
- **可选附加字段**（分析层按需产出，render 原样落盘）：
  - `negatives_raw`：全量否定词清单——否定词表 xlsx 只呈现各族代表词，全量在此留档供实施核对
  - `sheet2_mining`：源文件附加 sheet（如预分的"几乎不相关"类 sheet）的挖掘结论
- `root_dims`（token→维度映射）由 Agent 归纳注入，可选；`root_summary` 由 render 自动聚合写盘，Agent 无需手填。
- **数值分档字段**（`aba_tier` / `competition_score` / `competition_level` / `ppc_quadrant`）由 render 按固定界限确定性计算并覆盖写入（公式见 §3.1/§3.3），Agent 手填会被覆盖——保证同一输入永远同一输出。
